# Case 1285: explicit cut-set test

No production AAM changes. Ten ordinary random seed orders per cut set, original smaller-first P-to-R direction, tolerance 1, cap 2000, full explicit H. No node-label constraints or reference mappings were imposed on search. Cut sets were selected diagnostically from the reference, so success is not a blind benchmark recovery.

| Removed source edges | Reference recovered | Capped | Search + finalization + archive seconds |
|---|---|---|---:|
| None | No | No | 0.041 |
| C=O 7–8 | No | No | 0.040 |
| C–O 9–10 | No | Yes | 5.548 |
| Both C–O attachments | No | No | 0.691 |
| Both attachments plus O–H 10–20 | **Yes** | **No** | **0.072** |

Atom indices are planned search-source indices, not original RDF atom-map labels. Saved compressed-family verification certifies the last result. Search graphs and full verification witnesses are saved alongside every run.

The reference requires different carbonyl-oxygen assignments. Removing both C–O attachments alone still leaves a source OH fragment; an intact OH can match a different available OH site, whereas the reference needs its oxygen at a carbonyl site and its hydrogen elsewhere. Removing that O–H bond additionally exposes the necessary separate choices, and ordinary AAM finds the reference.

`cut_sweep_items` returns the no-cut case plus **independent single-edge cuts**. It never accumulates those three cuts in one work item. Therefore a full one-edge sweep does not automatically include this successful configuration. This test does not prove that three cuts are globally minimal, nor exclude a different seed ordering recovering with fewer cuts. Cut-dependent RNG streams also differ, as in the normal sweep.

Do not add unrestricted triple-cut enumeration: its cost and symmetry handling need a separate design discussion. No default, sweep logic, tolerance, cap, or benchmark score was changed.
